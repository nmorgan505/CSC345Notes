08 · Memory Management

Memory Management Background

  • Program has to be brought from disk to memory and placed in a process to run
  • This allocation should be as efficient as possible to accommodate both the OS and other processes.
  • Must allocate memory to ensure reasonable supply of ready processes

Requirements of Memory Management

  • Relocation
  • Protection
  • Sharing
  • Logical Organization
  • Physical Organization

Relocation

  • Programmers typically do not know in advance which other programs will be resident in main memory at the time of execution of their program
  • Active processes need to be able to be swapped in and out of main memory in order to maximize processor utilization
  • Specifying that a process must be placed in the same memory region when it is swapped back in would be limiting

Protection

  • Need to ensure that a process can access only those addresses in its address space
  • We can provide this protection by using a pair of base and limit registers to define the logical address space of a process

Hardware Address Protection

  • CPU must check (at runtime) every memory access generated in user mode to be sure it is between base and limit for that user
  • The instructions to load the relocation and limit registers are privileged

Sharing

  • Advantageous to allow each process access to the same copy of the program rather than have their own separate copy
  • Memory management must allow controlled access to shared areas of memory without compromising protection
  • Mechanisms used to support relocation support sharing capabilities

Logical Organization

  • The main memory is organized as a linear, or one dimensional address space, consisting of a sequence of bytes, but:
    • Programs are written in modules
    • Modules can be written and compiled independently
    • Different degrees of protection given to modules (read only, execute only)
    • Sharing on a module level corresponds to the way of viewing the problem

Physical Organization

  • Computer memory is organized into at least two levels:
    • Main memory (RAM)
    • Secondary storage (disk)
  • The flow of information between main memory and secondary memory is a major system concern
  • The responsibility for this flow should not be assigned to the individual programmer because:
    • Memory available for a program plus its data may be insufficient
    • Overlaying allows various modules to be assigned the same region of memory but is time consuming to the program
    • Programmer does not know how much space will be available

Types of Partitioning

  • Fixed: Main memory is divided into a number of static partitions at system generation time. A process may be loaded into a partition of equal or greater size
    • Disadvantages:
      • A program may not fit into a partition
      • Program needs to be designed with the use of overlays
      • Main memory utilization is inefficient
      • Internal fragmentation:
        • Wasted space due to the block of data loaded being smaller than the partition
      • The number of partitions specified at system generation time limits the number of active processes in the system
      • Small jobs will not utilize partition space efficiently
  • Dynamic: Partitions are created dynamically, so that each process is loaded into a partition of exactly the size of that process.
    • Was used by IBM’s mainframe OS OS/MVT
    • Issues:
      • External Fragmentation:
        • Memory becomes more and more fragmented
        • Memory utilization declines
      • Compaction:
        • Technique for overcoming external fragmentation
        • OS shifts processes so that they are contiguous
        • Free memory is together in one block
        • Time consuming and wastes CPU time
    • Uses 3 placement algorithms:
      • Best-fit
      • First-fit
      • Next-fit
  • Simple Paging: Main memory is divided into a number of equal size frames. Each process is divided into a number of equal size pages of the same length as frames. A process is loaded by loading all of its pages into available, if not necessarily contiguous, frames.
    • Pages are chunks of a process
    • Frames are available chunks of memory
    • The method uses a “Page Table”
      • Maintained by the OS for each process
      • Contains the frame location for each page in the process
      • Processor must know how to access for the current process
      • Used by the processor to translate logical addresses into physical addresses
      • Kept in main memory
    • Address Translation Scheme is used to convert logical address into physical address
      • Address generated by the CPU is divided into:
        • Page number (p): used as an index into a page table which contains base address of each page in physical memory
        • Page Offset (d): Combined with the base address to define the physical memory address that is sent to the memory unit.
  • Simple Segmentation: Each process is divided into a number of segments. A process is loaded by loading all of its segments into dynamic partitions that need not be contiguous
    • Segments may vary in length
    • There is a maximum length
    • Addressing consists of two parts:
      • Segment number
      • An Offset
    • Similar to dynamic partitioning
    • Eliminates internal fragmentation

  • Virtual memory paging: As with simple paging, except that it is not necessary to load all of the pages of a process. Nonresident pages that are needed are brought in later automatically.
  • Virtual memory segmentation: As with simple segmentation, except that it is not necessary to load all of the segments of a process. Nonresident segments that are needed are brought in later automatically.

Fragmentation

  • External Fragmentation:
    • Total memory space exists to satisfy a request, but is not contiguous
  • Internal Fragmentation:
    • Allocated memory may be slightly larger than requested memory; this size difference is memory internal to a partition, but not being used
  • First fit analysis reveals that given N blocks of allocated memory, 0.5 N blocks will be lost to fragmentation.

Buddy System

  • Comprised of fixed and dynamic partitioning schemes
  • Space available for allocation is treated as a single block
  • Memory blocks are available in size 2^k words, L <= k <= U where:
    • 2^L = smallest block that is allocated
    • 2^U = largest block that is allocated; usually, 2^U is the size of the entire memory available for allocation
  • Requested block sizes are rounded up to the nearest power of 2

Virtual Memory

  • Virtual memory is the separation of user logic memory from physical memory.
  • Importance:
    • Only part of the program needs to be in memory for execution
    • Logical address space can therefore be much larger than physical memory
    • Allows more efficient process creation
    • Less I/O needed to load or swap processes
    • More programs can be running concurrently
  • Virtual Memory Address Spaces:
    • Usually starts at address 0, contiguous addresses until the end of available space
    • Meanwhile physical memory is divided into frames
    • The physical page frames assigned to a process may not be contiguous
    • Memory management unit (MMU) maps logical to physical
  • Virtual memory can be implemented via:
    • Demand paging:
      • Load pages only as they are needed
      • If we want to run a process, we can either:
        • Load the entire process into memory at once
        • Only bring in pages as needed
          • This is more efficient, but complex
      • Demand paging is similar to paging system with swapping
    • Demand segmentation
  • Valid-Invalid Bit:
    • Each page table entry has a valid-invalid bit (v = in memory, i = not in memory)
    • Initially set to i on all entries
    • If the MMU encounters i during address translation, a page fault is triggered
  • Page Fault Handling:
    1. Trap to the OS
    2. Save user registers and process state
    3. Determine the interrupt was a page fault
    4. Check the page reference is legal; determine disk location
    5. Issue a disk read to a free frame
    6. Allocate CPU to another process while waiting
    7. Receive disk I/O interrupt when complete
    8. Restore registers and page table; resume interrupted instruction
  • Effective Access Time (EAT):
    • EAT = (1 - p) * memory access + p * (page fault overhead + swap page out + swap page in)
    • Where p = page fault rate (0 <= p <= 1)
  • Copy-on-Write (COW):
    • Allows parent and child processes to initially share the same pages in memory
    • If either process modifies a shared page, only then is the page copied
    • Allows more efficient process creation since only modified pages are copied

Page Replacement Algorithms

  • When no free frame is available, the OS must replace a page

  • Goal: minimize the number of page faults

  • FIFO (First-In, First-Out):

    • Replace the oldest page in memory
    • Simple to implement
    • Suffers from Belady’s Anomaly: adding more frames can sometimes cause more page faults, not fewer

  • Optimal Algorithm (OPT):

    • Replace the page that will not be used for the longest period of time in the future
    • Guarantees the minimum number of page faults
    • Cannot be implemented in practice (requires future knowledge)
    • Used as a benchmark to evaluate other algorithms

  • Least Recently Used (LRU):

    • Replace the page that has not been used for the longest time in the past
    • Uses past knowledge as an approximation of future behavior
    • Generally a good algorithm; does not suffer from Belady’s Anomaly
    • More complex to implement than FIFO

  • Counting Algorithms (less common):

    • Least Frequently Used (LFU): replace page with smallest reference count
    • Most Frequently Used (MFU): replace page with largest reference count (reasoning: smallest count was likely just brought in)

Thrashing

  • If a process does not have enough frames, the page-fault rate becomes very high
  • The process spends more time paging than executing
  • Leads to very low CPU utilization
  • OS may respond by increasing multiprogramming, making the problem worse
  • Occurs when: total size of localities > total memory size

Secondary Storage

  • Hard Disk Drives:

    • Platters range from .86” to 14” (historically)

    • 3.5”, 2.5” and 1.8” are the most common sizes

    • Range from 30GB to 12TB, and growing

    • Transfer rates reach theoretical rates of 6 Gb/sec, but are more realistically around 1 Gb/s

    • Seek time ranges from 3ms to 12ms, where 9ms is common on desktop drives

    • Latency is the time it takes for the disk to spin

    • Average latency = 1/2 the time it takes for a full rotation

    • HDDs spin platters of magnetic material at high speeds under a read-write head

    • Transfer rate is the rate at which data flows between the disk and a computer

    • Positioning/Access time is the time taken to move the disk arm to the desired cylinder (seek) and time for the desired sector to rotate under the disk head (rotational latency)

    • Head crash results when the read-write head touches the platter

      • This is really bad

    • Disk Performance Parameters:

      • The actual details of disk I/O operation depend on:
        • Computer System (hardware)
        • Operating System
        • Nature of the I/O channel and disk controller
      • On a moveable-head system, the time it takes to position the head at the track is known as seek time
      • The time it takes for the beginning of the sector to reach the head is known as rotational delay, or latency
      • The sum of the seek time and the rotational delay is known as the access time

    • Seek time:

      • The time required to move the disk arm to the required track
      • Three key components of seek time:
        • Startup time: The time it takes to accelerate the arm to its maximum speed
        • Settling time: The time after positioning the head over the target track until track identification is confirmed
      • Typical seek time is under 10ms

    • Rotational Delay:

      • The time required for the addressed area of the disk to rotate into a position where it is accessible by the read-write head
      • Disk rotates at speeds ranging from 3600 to 15000 RPM

    • Transfer time:

      • The transfer time to or from the disk depends on the disk rotation speed

    • Performance:

      • Average access time is the sum of the average seek time and latency
        • For fast disks, 3ms + 2ms = 5ms
        • For slow disks, 9ms + ~5.56ms = 14.56ms

    • Example:

      • To transfer a 4KB block of data on a 7200 RPM disk with a 5ms average seek time, 1 Gb/sec transfer rate with a .1ms controller overhead:
        • 5ms + 4.17ms + transfer time =
        • Transfer time = 4 KB / 1 Gb/sec * 8Gb/GB * 1 GB / 1024^2KB = 32/(1024^2) = 0.00003051758 s or .031 ms
        • Average I/O time for 4KB block = 9.27ms + .031ms = 9.301ms

    • Other Nonvolatile Memory:

      • If disk-drive like, then called solid-state disks (SSD)
      • Other forms include USB drives (thumb drives, flash drives), DRAM disk replacements, surface mounted motherboards, and main storage in devices like smartphones and tablets
      • Can be more reliable than HDDs
      • More expensive per GB
      • Generally less capacity, but much faster
      • No moving parts, so no seek time or rotational latency

    • HDD Scheduling:

      • The OS is responsible for using hardware efficiently — for disk drives, this means having a fast access time and disk bandwidth
        • Minimize seek time
          • seek time ~= seek distance
      • Disk Bandwidth is the total number of bytes transferred, divided by the total time between the first request for service and the completion of the last transfer
      • We can improve both the access time and the bandwidth by managing the order in which storage I/O requests are serviced
      • There are many sources of disk I/O requests:
        • User processes
        • System processes
        • OS
      • I/O request includes mode, disk address, memory address, and number of sectors to transfer
      • OS maintains a queue of requests
      • Idle disk can immediately work on I/O request, but busy disk means work must queue
        • This means we must use optimization algorithms to determine the order in which to service requests
      • In the past, the OS was responsible for queue management and disk drive head scheduling, but now it is usually built into the storage devices or controllers.
  • Hard Drive Algorithms:

    • Queue of requests: 98, 183, 37, 122, 14, 124, 65, 67

    • Assume the disk head is at 53

    • The disk is divided into 200 cylinders, numbered 0-199

    • FCFS (FIFO):

      • First Come First Serve
      • The requests are serviced in the order they arrive
      • Measure the total distance traveled by the disk head as a check of efficiency

    • SCAN:

      • The disk arm starts at one end of the disk and moves toward the other end, servicing requests until it reaches the other end, then reverses direction and services requests on the way back
      • Also called the elevator algorithm

    • C-SCAN:

      • Provides a more uniform wait time than SCAN
      • The head moves from one end of the disk to the other, servicing requests as it goes.
        • When it reaches the end, it immediately returns to the beginning of the disk, without servicing any requests on the return trip
      • Treats the cylinders as a circular list that wraps around from the last cylinder to the first one.

    • N-Step-SCAN:

      • Segments the disk request queue into subqueues of length N
      • Subqueues are processed one at a time, using SCAN
      • While a queue is being processed, new requests must be added to some other queue
      • If fewer than N requests are available at the end of the scan, all of them are processed with the next scan

    • FSCAN:

      • Uses two subqueues
      • When a scan begins, all of the requests are in one of the queues, with the other empty
      • During SCAN, all new requests are put into the other queue
      • Service of new requests is deferred until all of the old requests have been processed

    • Shortest Service Time First (SSTF):

      • Select the disk I/O request that requires the least movement of the disk arm from its current position
      • Always choose the minimum seek time
      • Common and has natural appeal, but can cause starvation
      • SCAN and C-SCAN perform better for systems under heavy disk load and have less starvation

    • Choosing an Algorithm:

      • SSTF is common and has a natural appeal with good performance
      • SCAN and C-SCAN perform better for systems that place a heavy load on the disk
        • Generally less starvation
      • To avoid starvation, Linux implements deadline scheduler
        • Maintains separate read and write queues, gives read priority
        • Because processes more likely to block on read than write

    • Track: A circular path on disk where data is recorded, structured like rings on a tree, where tracks are labeled starting from 0 on the outside and increasing as you move toward the center of the disk

    • Cylinder: A stack of tracks

    • Sector: A portion of a track, usually 512 bytes, but modern disks can have larger sectors, such as 4KB. These are grouped into blocks

  • Average Latency Computation:
    • Average latency = 1/2 * (1/RPM) * 60 seconds/minute
      • For a 7200 RPM disk: average latency = 1/2 * (1/7200) * 60 = 4.17ms
  • Equations to consider:
    • Rotational Latency = (60,000ms / x RPM)
    • Average Rotational Latency = 1/2 * Rotational Latency
    • Transfer Time (ms) = (Block Size (GB)) / (Transfer Rate (GB/s)) * (8Gb/s / 1 GB/s) * (1000ms / 1s) = Rotational Latency / # of sectors
    • Total Transfer Time = Avg Seek + Controller Overhead + Transfer Time
    • Average Access Time = Average Seek Time + Average Rotational Latency + Average Transfer Time
    • Average I/O time = Average Access Time + (amount to transfer / transfer rate) + controller overhead
    • Transfer rate (bytes/ms) = total track size (bytes) / one disk rev (ms)
    • Total Capacity of cylinder = # of platters * # of platter sides used * total capacity of a track
    • Total capacity of a track = capacity of cylinder * number of cylinders
    • Total capacity of a track = (sector size) * (sectors/track)
    • Time to transfer x amount of data = (x bytes) / (transfer rate in bytes/ms)
    • Avg time to locate and transfer a single sector (ms) = (avg seek time) + (avg rotational latency) + (1/RPM/60000)
    • Avg time to transfer x random sectors (ms) = (x # of sectors) * (avg time to locate and transfer a single sector)
    • Avg time to transfer x consecutive sectors (ms) = Average seek time + avg rotational latency + (x * sector size) / (transfer rate in bytes/ms) + controller overhead
